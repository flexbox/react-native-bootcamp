# Generate a typed API client with Orval

## 📡 What you will learn

- Describe a REST API with an [OpenAPI](https://www.openapis.org/) spec.
- Generate typed `react-query` hooks with [Orval](https://orval.dev/).
- Send every request through one custom `fetch` function.

## 👾 Before we start the exercise

- [ ] Finish the [`react-query` challenge](./02.md): you need `QueryClientProvider` and your `useStarships()` hook.
- [ ] Have a look at the [Orval React Query guide](https://orval.dev/docs/guides/react-query)

In the previous challenge you wrote the API layer by hand: a `fetch` function, a `queryKey`, a `useQuery` hook and, for TypeScript, the `StarshipProps` type. It works for one endpoint, but every new endpoint repeats that code, and nothing tells you when your types no longer match the API.

An **OpenAPI spec** is a YAML (or JSON) file that describes an API: its URLs, its parameters and the shape of every response. **Orval** reads that spec and writes the API layer for you:

1. A typed `fetch` function per endpoint (_here `listStarships` and `getStarship`_).
1. A `queryKey` per endpoint, built from its URL and parameters.
1. A `react-query` hook per endpoint (_here `useListStarships` and `useGetStarship`_).
1. A TypeScript type per response (_here `Starship` and `StarshipList`_).

SWAPI doesn't publish an OpenAPI spec, so we wrote one for you: [`swapi.yml`](./swapi.yml). It describes the starships endpoints.

### Add the OpenAPI spec

- [ ] Download the spec into an `api` folder at the root of your project

```console
mkdir -p api
curl -o api/swapi.yml https://raw.githubusercontent.com/flexbox/react-native-bootcamp/main/challenges/data/swapi.yml
```

- [ ] Take 5 min to **read carefully** `api/swapi.yml`:
  - `paths` lists the endpoints: `/starships/` and `/starships/{id}/`.
  - Each `operationId` becomes a function name: `listStarships` → `useListStarships()`.
  - `components.schemas` describes the responses: each schema becomes a TypeScript type.

**🔭 Hint:** SWAPI returns every value as a string, numbers included (`"3500000"`, `"unknown"`, `"30-165"`). The spec types them as `string` so the generated types match what the API really sends.

### Install and configure Orval

- [ ] Install Orval as a dev dependency: it runs on your computer, not in the app

```console
npm install --save-dev orval
```

- [ ] Create the `fetch` function every generated request will go through

```ts
// ./src/api/fetcher.ts
export const swapiFetch = async <T>(
  url: string,
  options: RequestInit,
): Promise<T> => {
  const response = await fetch(url, options);

  if (!response.ok) {
    // Throwing puts the query in its `isError` state
    throw new Error(`SWAPI error ${response.status} on ${url}`);
  }

  return response.json();
};
```

`fetch` only rejects when the network fails. A `404` or a `500` still resolves, so we throw ourselves. This function is also the one place to add headers later, like an auth token.

**🔭 Hint:** Orval calls this function a [custom client](https://orval.dev/docs/guides/custom-client).

- [ ] Create `orval.config.ts` at the root of your project

```ts
// ./orval.config.ts
import { defineConfig } from "orval";

export default defineConfig({
  swapi: {
    input: "./api/swapi.yml",
    output: {
      // Reads `servers[0].url` from the spec: https://swapi.py4e.com/api
      baseUrl: { getBaseUrlFromSpecification: true },
      client: "react-query",
      httpClient: "fetch",
      // Hooks in swapi.ts, types in swapi.schemas.ts
      mode: "split",
      override: {
        fetch: {
          // Return the JSON body, like `swapiFetch` does
          includeHttpResponseReturnType: false,
        },
        mutator: {
          name: "swapiFetch",
          path: "./src/api/fetcher.ts",
        },
      },
      target: "./src/api/swapi.ts",
    },
  },
});
```

- [ ] Add a script to `package.json`

```json
"scripts": {
  "api:generate": "orval"
}
```

- [ ] Generate the client

```console
npm run api:generate
```

You should now have two new files:

- `src/api/swapi.ts`: `listStarships`, `useListStarships`, `getStarship`, `useGetStarship`…
- `src/api/swapi.schemas.ts`: `Starship`, `StarshipList`, `ListStarshipsParams`…

**🔭 Hint:** Never edit these two files by hand: the next `npm run api:generate` overwrites them. To change the API layer, change `api/swapi.yml` or `orval.config.ts`, then generate again.

### Use the generated hooks

- [ ] In `StarshipFeedScreen`, replace your `useStarships()` hook with the generated `useListStarships()`

```tsx
// READ AND ADAPT; DO NOT MONKEY COPY/PASTE ME
import { useListStarships } from "@/api/swapi";

export const StarshipFeedScreen = () => {
  const { data, isError, isPending, refetch } = useListStarships();

  // …your loading and error states stay the same

  return (
    <FlatList
      data={data.results} // typed as Starship[]
      keyExtractor={(ship) => ship.url}
      renderItem={renderItem}
    />
  );
};
```

### Infinite scroll

SWAPI returns 10 starships per page, and `next` holds the URL of the next page.

- [ ] Ask Orval for an infinite query hook in `orval.config.ts`, then run `npm run api:generate` again

```ts
override: {
  // …
  query: {
    useInfinite: true,
    useInfiniteQueryParam: "page",
  },
},
```

- [ ] Load the next page when the user reaches the end of the `FlatList`

```tsx
// READ AND ADAPT; DO NOT MONKEY COPY/PASTE ME
const { data, fetchNextPage, hasNextPage, isFetchingNextPage } =
  useListStarshipsInfinite(undefined, {
    query: {
      initialPageParam: 1,
      getNextPageParam: (lastPage) => {
        if (!lastPage.next) {
          return undefined; // last page
        }
        return Number(new URL(lastPage.next).searchParams.get("page"));
      },
    },
  });

const starships = data?.pages.flatMap((page) => page.results) ?? [];

<FlatList
  data={starships}
  onEndReached={() => {
    if (hasNextPage && !isFetchingNextPage) {
      fetchNextPage();
    }
  }}
  // …
/>;
```
