Following the [documentation to add variants to your application](https://docs.expo.dev/build-reference/variants/#example-configuring-development-and-production-variants-in):

- [ ] create your `app.config.ts` to use in your project (here is [the one used by spacecraft](https://github.com/flexbox/react-native-bootcamp/blob/main/hackathon/spacecraft/app.config.ts))
  - add a custom name for your dev app

Let's say now you want to have differents API endpoints. You can use [environment variables](https://docs.expo.dev/guides/environment-variables/) to do that. Don't forget to follow the [`.env` convention](https://github.com/bkeepers/dotenv/blob/c6e583a/README.md#what-other-env-files-can-i-use).

- [ ] create a `.env.local` file and add your environment variables.

```console
EXPO_PUBLIC_API_URL=https://swapi.py4e.com/
```

- [ ] use `process.env.EXPO_PUBLIC_API_URL` to call the Star Wars API in your app.

In real situations, you may have multiple endpoints depending on the environment. EAS has 3 environments out of the box: `development`, `preview` and `production`. Here is how [you can use them with your build profiles](https://docs.expo.dev/eas/environment-variables/).

🔥 Never commit sensitive information!

If you need a secret key like `SENTRY_AUTH_TOKEN`, don't put it in your repository: store it as an [EAS environment variable](https://docs.expo.dev/eas/environment-variables/) with the `secret` visibility.

To create a new variable, run:

```console
eas env:create   # create a new environment variable
eas env:list     # view existing variables for an environment
eas env:pull     # download them into your local .env.local file
```

**🔭 Hint:** Every `EXPO_PUBLIC_` variable is inlined in your JavaScript bundle and readable by anyone who downloads your app. Never prefix a real secret with `EXPO_PUBLIC_`.

- [ ] use `eas env:create` and create a fake `SWAPI_KEY` because there is no API key for the Star Wars API.
