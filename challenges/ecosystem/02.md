Prettier is an opinionated code formatter. It enforces a consistent style by parsing your code and re-printing it with its own rules that take the maximum line length into account, wrapping code when necessary.

### Setup ESLint

- [ ] Setup ESLint in your project with the following command:

```console
npx expo lint
```

- [ ] Answer **yes** to the following question:

```console
✔ No ESLint config found. Install and configure ESLint in this project?
```

You will have a `eslint.config.js` file created at the root of your project.

### Run ESLint from the terminal

- [ ] Update your scripts on `package.json` to check errors.

```json
// package.json

  "scripts": {
    ...
     "lint": "eslint ."
    ...
  }
```

**🔭 Hint:** Files to lint and files to ignore are declared directly in `eslint.config.js`.

Now you can run the `lint` script to tell if you have errors

```console
npm run lint
# or
yarn lint
```

Running lint will show you errors in your code, here is an example:

![yarn lint](https://raw.githubusercontent.com/flexbox/react-native-workshop/main/challenges/ecosystem/eslint-cli.gif)

You don't need to manually fix your errors. We can run a script for that with:

```console
npm run lint -- --fix
# or
yarn lint --fix
```

- [ ] Run `--fix` to automatically fix your errors.
- [ ] Commit your work.
- [ ] Push your project to GitHub to have a backup.

**🔭 Hint:** if you encounter a difference between errors on your terminal and VSCode, reload VSCode with `⌘ + ⇧ + P` "Developer: Reload Window".

### Prettier

- [ ] Install the following dependencies

```console
npm install --save-dev prettier eslint-config-prettier eslint-plugin-prettier
# or
yarn add --dev prettier eslint-config-prettier eslint-plugin-prettier
```

- [ ] Update your `eslint.config.js` file to add the Prettier recommended config:

```javascript
// eslint.config.js

const expoConfig = require("eslint-config-expo/flat");
const prettierRecommended = require("eslint-plugin-prettier/recommended");
const { defineConfig } = require("eslint/config");

module.exports = defineConfig([
  {
    ignores: ["node_modules/**", ".expo/**", "dist/**", "ios/**", "android/**"],
  },
  expoConfig,
  prettierRecommended, // enables `eslint-plugin-prettier` + `eslint-config-prettier`
]);
```

### ESLint and prettier rules for React Native

We are making progress, but we are not done yet. We need to add rules for TypeScript and React.

- [ ] Install the following plugins

```console
npm install --save-dev @eslint/js@^9 @typescript-eslint/eslint-plugin @typescript-eslint/parser eslint-plugin-react globals
# or
yarn add --dev @eslint/js@^9 @typescript-eslint/eslint-plugin @typescript-eslint/parser eslint-plugin-react globals
```

**🔭 Hint:** Keep `@eslint/js` on the same major version as `eslint` (v9 here). The latest `@eslint/js` targets ESLint 10 and npm will fail with an `ERESOLVE` error.

- [ ] Update your `eslint.config.js` file to add the following rules:

```javascript
// eslint.config.js

const js = require("@eslint/js");
const tseslint = require("@typescript-eslint/eslint-plugin");
const expoConfig = require("eslint-config-expo/flat");
const prettierRecommended = require("eslint-plugin-prettier/recommended");
const react = require("eslint-plugin-react");
const { defineConfig } = require("eslint/config");
const globals = require("globals");

module.exports = defineConfig([
  {
    ignores: ["node_modules/**", ".expo/**", "dist/**", "ios/**", "android/**"],
  },
  expoConfig,
  js.configs.recommended, // ESLint rules
  tseslint.configs["flat/recommended"], // TypeScript rules
  react.configs.flat.recommended, // React rules
  react.configs.flat["jsx-runtime"], // No need to `import React` in every file
  prettierRecommended, // Prettier rules
  {
    languageOptions: {
      globals: {
        ...globals.node,
      },
    },
    rules: {
      "@typescript-eslint/no-require-imports": "off", // allow `require()` for static assets
      "@typescript-eslint/no-unused-vars": "warn", // detect unused variables
      "prettier/prettier": [
        "warn",
        {
          usePrettierrc: true,
        },
      ],
    },
  },
]);
```

- [ ] Create a `.prettierrc` file at the root of your project with the following content:

```json
// .prettierrc

{
  "$schema": "http://json.schemastore.org/prettierrc",
  "semi": true,
  "singleAttributePerLine": true,
  "trailingComma": "all",
  "tabWidth": 2,
  "singleQuote": false
}
```

**🔭 Hint:** Windows users can add `"endOfLine": "crlf"`. Don't paste the `// .prettierrc` comment: the file must be valid JSON.

### Updating ESLint rules

We want to add some rules to our ESLint configuration.

```console
npm install --save-dev eslint-plugin-react-native
# or
yarn add --dev eslint-plugin-react-native
```

- [ ] Update your `eslint.config.js` file to add the following react-native rules:

```javascript
// eslint.config.js

const reactNative = require("eslint-plugin-react-native");

// Add to your last config object:
{
  plugins: {
    "react-native": reactNative,
  },
  rules: {
    ...
    "react-native/no-color-literals": 2, // enforce color literals are not used
    "react-native/no-raw-text": 0, // detect raw text outside of Text component
    "react-native/no-unused-styles": 2, // detect unused StyleSheet rules
    "react-native/sort-styles": 2, // enforce style definitions are sorted
  },
}
```

- [ ] Lint your code and push your changes to GitHub.

We now want to sort our imports (and objects, interfaces…) automatically. We can use the [`perfectionist`](https://perfectionist.dev/) plugin.

```console
npm install --save-dev eslint-plugin-perfectionist
# or
yarn add --dev eslint-plugin-perfectionist
```

- [ ] Update your `eslint.config.js` file to add the following sorting rules:

```javascript
// eslint.config.js

const perfectionist = require("eslint-plugin-perfectionist");

module.exports = defineConfig([
  ...
  prettierRecommended,
  perfectionist.configs["recommended-natural"], // sort everything with a natural order
  {
    ...
    rules: {
      ...
      "perfectionist/sort-imports": "error", // https://perfectionist.dev/rules/sort-imports
      "perfectionist/sort-interfaces": "error",
      "perfectionist/sort-modules": "off",
    },
    settings: {
      perfectionist: {
        partitionByComment: true,
        type: "line-length",
      },
    },
  },
]);
```

- [ ] Lint your code and push your changes to GitHub.

**🔭 Hint:** `perfectionist` also sorts object keys, so `useQuery({ queryKey, queryFn })` becomes `useQuery({ queryFn, queryKey })`. It works, but if you prefer TanStack Query's order, copy the `perfectionist/sort-objects` exception from [the spacecraft config](https://raw.githubusercontent.com/flexbox/react-native-bootcamp/main/hackathon/spacecraft/eslint.config.js).

We have no control on the api data we are pulling from SWAPI. Sometimes we want to update our rules to reflect differences.

In our case `cargo_capacity`, `cost_in_credits` are not using `camelCase` and we want to disable this rule.

- [ ] Update your `eslint.config.js` file to add the following rules:

```javascript
// eslint.config.js

{
  rules: {
    ...
    camelcase: "off", // disable camelcase rule
    "@typescript-eslint/no-explicit-any": "warn", // detect usage of `any` type
  },
}
```

- [ ] Lint your code and push your changes to GitHub.

## 👽 Bonus

### Share your settings with your team

You can share your VSCode settings with your team by adding a `.vscode` folder at the root of your project with the following content.

This will make sure everyone in your team is using the same settings.

```json
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "dbaeumer.vscode-eslint",
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "always"
  }
}
```

- [ ] create a `.vscode` folder.
- [ ] create a `settings.json` file.
- [ ] Add the content above.

- [ ] Install [TanStack Query ESLint plugin](https://tanstack.com/query/latest/docs/eslint/eslint-plugin-query) and add `pluginQuery.configs["flat/recommended"]` to your `eslint.config.js`.
