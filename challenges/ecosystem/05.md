# Unit Testing with React Native

## 📡 What you will learn

- Write maintainable unit tests with good testing practices.
- Use React Native Testing Library (`RNTL`) —a lightweight solution for testing React Native components.

## 👾 Before we start the exercise

Unit tests cover the smallest parts of code, like individual functions or components.

We are writing unit tests to avoid regressions over time. Creating a brand new app is easy, maintaining it over time is way more complex.

> `RNTL` is a very light-weight solution for testing without all the implementation details. The main utilities it provides involve querying for nodes similarly to how users would find them. In this way, testing-library helps ensure your tests give you confidence in your UI code.

- Check [`RNTL` documentation](https://oss.callstack.com/react-native-testing-library/docs/start/quick-start)

### How to write your first test

The main concept is to test how your user will "see" your application and ensure your component renders correctly.

Here's an example of a `*.test.tsx` file:

```javascript
describe('', () => {
  it('', () => {

  });
});
```

### Adding description

We will test if `Header.test.tsx` renders correctly:

```javascript
// Header.test.tsx

describe('Header', () => {
  it('renders correctly', () => {

  });
});
```

### Render the component

You need to `render` the component you want to test with `props` declaration.

**🔭 Hint:** Since React Native Testing Library v14, `render`, `fireEvent` and `act` are **async**: always mark your test `async` and `await` them.

```javascript
// Header.test.tsx

import { render } from "@testing-library/react-native";

import { Header } from "./Header";

describe("Header", () => {
  it("renders correctly", async () => {
    await render(<Header title="SpaceCraft" />);

  });
});
```

### Debug the component

The first time you can use `debug()` to print rendered component.

```javascript
// Header.test.tsx

import { render, screen } from "@testing-library/react-native";

import { Header } from "./Header";

describe("Header", () => {
  it("renders correctly", async () => {
    await render(<Header title="SpaceCraft" />);

    screen.debug();
  });
});
```

### Automatically detect if text is rendered

`getByText` is the method used to find any visible text on interactive and non-interactive elements —like a user will "see" our component. `toBeVisible()` is one of the [built-in Jest matchers](https://oss.callstack.com/react-native-testing-library/docs/api/jest-matchers) shipped with RNTL.

```javascript
// Header.test.tsx

import { render, screen } from "@testing-library/react-native";

import { Header } from "./Header";

describe("Header", () => {
  it("renders correctly", async () => {
    await render(<Header title="SpaceCraft" />);

    expect(screen.getByText("SpaceCraft")).toBeVisible();
  });
});
```

When you run your `test` command, you will see green boxes if everything works!

### Setup Jest

- [ ] Install the Jest package, as well as an Expo-specific Jest preset package:

```console
npx expo install jest-expo jest @types/jest -- --save-dev
```

- [ ] Update `package.json` with a new script to run Jest

```diff
   "scripts": {
     "start": "expo start",
     "android": "expo start --android",
     "ios": "expo start --ios",
--    "web": "expo start --web"
++    "web": "expo start --web",
++    "test": "jest"
   },
++  "jest": {
++    "preset": "jest-expo"
++  },
```

### Double check Jest setup

- [ ] Create a new file called `hello.test.ts` and paste this working test

```javascript
// ./src/utils/hello.test.ts

it("works", () => {
  expect(1).toBe(1);
});
```

When you run `npm run test` you should have this result

```console
$ jest
 PASS  src/utils/hello.test.ts

Test Suites: 1 passed, 1 total
Tests:       1 passed, 1 total
Snapshots:   0 total
Time:        7.029 s
Ran all test suites.
```

At this point, TypeScript will complain about `it` and `expect` in your `hello.test.ts` file: you need to list the `jest` types in your `tsconfig.json`.

- [ ] Add the `jest` types to your `tsconfig.json`:

```diff
{
  "extends": "expo/tsconfig.base",
  "compilerOptions": {
    "strict": true,
++  "types": ["jest"]
  }
}
```

### Installing React Native Testing Library

- [ ] Install `@testing-library/react-native` and its peer dependency `test-renderer`:

```console
npx expo install react-dom
npm install --save-dev @testing-library/react-native test-renderer
```

**🔭 Hint:** `npx expo install react-dom` pins `react-dom` to the exact `react` version of your Expo SDK. Without it, npm may pull a newer `react-dom` and fail with an `ERESOLVE` peer dependency error.

- [ ] Follow the [getting started guide](https://oss.callstack.com/react-native-testing-library/docs/start/quick-start).

**🔭 Hint:** RNTL extends Jest with its matchers (`toBeVisible`, `toHaveTextContent`…) automatically as soon as you import anything from `@testing-library/react-native`.

For `setupFilesAfterEnv`, i like to extract it to a separate file because it's easier to maintain (mocks, fake timers…). Here is [an example of a `jest.setup.js` file](https://github.com/flexbox/react-native-bootcamp/blob/main/hackathon/spacecraft/jest.setup.js).

- [ ] Update `setupFilesAfterEnv` to your `package.json`

```diff
  "jest": {
    "preset": "jest-expo",
+    "setupFilesAfterEnv": [
+      "<rootDir>/jest.setup.js"
+    ]
  },
```

- [ ] Create a `jest.setup.js` file. This is where you mock native modules, for example if you use `react-native-gesture-handler` and `react-native-reanimated`:

```javascript
// jest.setup.js

import "react-native-gesture-handler/jestSetup";

jest.mock("react-native-worklets", () =>
  require("react-native-worklets/src/mock"),
);
```

Let's now create a workflow to quickly add units tests on your codebase.

- [ ] update `package.json` with a param to watch the file we change

```diff
// package.json

  "test": "jest",
+  "test:watch": "jest --watch"
```

Now you can run `npm run test:watch` to watch your files and run tests automatically.

#### Improve your ESLint setup

- [ ] Install [eslint-plugin-testing-library](https://github.com/testing-library/eslint-plugin-testing-library) and enable it for test files only in your `eslint.config.js`:

```javascript
// eslint.config.js

const testingLibrary = require("eslint-plugin-testing-library");

module.exports = defineConfig([
  ...
  {
    // Test files only
    files: ["**/__tests__/**/*.[jt]s?(x)", "**/?(*.)+(spec|test).[jt]s?(x)"],
    ...testingLibrary.configs["flat/react"],
  },
]);
```
